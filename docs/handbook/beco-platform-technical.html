AKey decisions

Beco sells interior materials through multi item quotations, not a checkout. Everything here serves one job: a salesperson raises, prices and issues a branded quote from a phone faster than writing it on paper.

Sources of truth. This handbook summarises the repository as released on 13 October 2026 (main at 65ac22d, both databases at migration 71). Where it and the code disagree, the code wins. The committed docs in docs/ go deeper: DECISIONS.md (why), SCHEMA.md, SECURITY.md, DEPLOYMENT.md, RUNBOOK.md, HANDOVER.md, QA-CHECKLIST.md. CLAUDE.md holds the project rules every change must keep.

Public

Storefront, www.beco.co.ke

Catalogue by range, product pages with price or price on request, a quote list kept in the browser, and a submission that becomes a quote in the database. Blog, gallery, team, contact. Statically generated and revalidated hourly or on demand.

Staff

Dashboard, dashboard.beco.co.ke

Quotes (table and board), counter quotes on a phone, orders and receipts, customers, catalogue and photographs, announcements, reports, users and permissions, settings, audit. Studio (blog drafting) lives inside it, Brightex only.

Principles that shape every file

  • The database is the authority. Row level security is deny by default on every table; changes to quote lines and statuses go through Postgres functions that enforce the business rules and an optimistic lock.
  • Checked in two places. Route access is decided by one map (apps/dashboard/src/lib/access.ts) in the proxy and in every page and action, and again by RLS. Hiding a button is never access control.
  • Everything is tested. Unit, component (jsdom), integration against a local Supabase, and pgTAP tests for every policy from every role. No browser automation in the suite; journeys are walked by hand against docs/QA-CHECKLIST.md.
  • Beco owns its accounts. Data, DNS, images and email are on Beco's accounts; Brightex holds only the repository and the Vercel projects.
  • House rules enforced by CI: no em dashes anywhere, no browser dialogs (ConfirmDialog and toast() instead), a 16px type floor, verified contrast.

Functions that carry the business rules

  • submit_quote: the only public write. Recomputes prices from the catalogue, links or creates the customer, in one transaction.
  • create_counter_quote, add_catalogue_quote_lines (one lock, takes a size), add_custom_quote_line, update_quote_lines, remove_quote_line: every line change, guarded by assert_quote_lines_open so a won, lost or converted quote cannot change.
  • set_quote_status: forward only, lost needs a reason, won and lost are closed; reopen_quote is the only way back from lost.
  • refresh_quote_money, refresh_order_money: totals by trigger. Prices include VAT and the documents back it out (D50).
  • convert_quote_to_order, set_order_status, mark_order_paid.
  • Access helpers: current_user_role() (null when inactive), is_admin(), is_brightex_user(), has_module(), can_grant_module(), has_staff_manage().
  • A stale lock raises SQLSTATE PT409 everywhere; the UI turns it into "This quote changed while you were editing".

The other flows, briefly

  • Counter quote. /quotes/new on a phone: customer, lines from the catalogue (one row per size) or custom, any price typed with the list price kept beside it. A line priced away from the catalogue sets requires_approval; any later line change clears the approval.
  • Won to paid. convert_quote_to_order copies the prices; the order moves to confirmed and fulfilled; mark_order_paid stamps the date; the receipt PDF comes from the order. Stock is not decremented automatically.
  • Drive import. Brightex starts it from /products/import, which dispatches drive-import.yml; the job reads the Drive tree, plans by md5, uploads derivatives to R2 and upserts by source_path, never overwriting prices Beco has set. Needs GITHUB_ACTIONS_TOKEN, not yet set.
  • Blog. Studio sends a brief to Gemini, a validator rejects em dashes, banned phrases and long meta, a person edits and checks the claims, the cover needs alt text, publishing revalidates the blog and sitemap.
  • Announcement bar. Admins schedule it; the shop renders the live one with the highest priority server side, height reserved.
08
Defence in depth
Security
Headers

An explicit policy on both apps

CSP with default-src 'self', frame-ancestors 'none', object-src 'none', upgrade-insecure-requests; HSTS a year; X-Frame-Options DENY; nosniff; strict referrer; camera, microphone and location denied. The dashboard adds 'wasm-unsafe-eval' for the HEIC decoder and noindex. 'unsafe-inline' scripts remain a known compromise.

Input

Validated on the server

zod on every action; client checks are for convenience only. Safe return paths, constant time secret comparison.

Secrets

Service role stays on the server

Used only for account creation and the import job. Never in a NEXT_PUBLIC_ variable; CI's secret scan fails the build if it leaks.

Accounts

Staff only, no public signup

Supabase Auth; forced password change on first sign in; deactivation makes the role null so RLS closes and sessions end. No MFA yet (deferred, D83).

Rate limit (in memory, per instance)Limit
Website quote submission10 a minute per IP (documents say 5; the code is the truth)
Dashboard sign in10 a minute per address
Drive import dispatch1 a minute per person
/api/ops-alert, /api/quote-confirmation60 a minute each

The in memory limiter is a brake, not a wall. A Cloudflare edge rule on POST to the quote and contact endpoints is the intended backstop and should be confirmed.

Soft delete and audit. Products, quotes, orders and customers carry deleted_at; users are deactivated. Audit triggers record every change to commercial tables with who and before and after.
